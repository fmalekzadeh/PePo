Installing Petit Pomme

A local, OpenAI-compatible API in front of Apple's on-device Foundation Model.

Requirements

  • macOS 26 or later
  • Apple Intelligence enabled (Settings → Apple Intelligence & Siri)

1. Get the app

Copy Petit Pomme.app to your Mac, then drag it into your Applications folder (or wherever you keep apps — it doesn't need to live in /Applications to run).

2. First launch

Petit Pomme isn't distributed through the App Store and isn't signed with an Apple Developer ID — it's a personal, self-built tool, signed only "ad-hoc" on the machine that built it. The first time you open it, macOS's Gatekeeper will likely block it with a message like:

"Petit Pomme.app" is damaged and can't be opened. You should move it to the Trash.

— or —

Apple could not verify "Petit Pomme.app" is free of malware that may harm your Mac or compromise your privacy.

Despite the alarming wording, this just means the app's signature isn't from a path Gatekeeper already trusts — it's not a verdict that anything is actually wrong with it. There are two ways past it:

Option A — right-click to open (no Terminal)

  1. In Finder, Control-click (or right-click) Petit Pomme.app.
  2. Choose Open from the menu.
  3. In the dialog that appears, click Open Anyway (you may need to approve this once more in System Settings → Privacy & Security, near the bottom of the page).

Option B — clear it from Terminal

If Option A doesn't offer an "Open Anyway" button (common for apps copied over AirDrop, a USB drive, or certain network shares), the app has a quarantine flag attached to it. Clear it with: 

xattr -cr "/Applications/Petit Pomme.app"

(Adjust the path if you put the app somewhere other than /Applications.) Then just double-click the app normally — it should open without complaint.

This is not the same thing as disabling SIP. System Integrity Protection (SIP) locks down core parts of macOS itself, and turning it off system-wide (csrutil disable) weakens real security protections for every app on your Mac — there's no reason to do that here, and this guide never asks you to. The command above only removes a quarantine attribute (Gatekeeper's "where did this come from" flag) from this one app. SIP stays fully enabled the whole time.

3. Run it

A small apple icon appears in your menu bar. Click it, flip the Server switch on, and it starts listening on http://127.0.0.1:<port> (loopback only — it's never reachable from the network). Use the built-in Test Chat window to confirm it's working, or point any OpenAI-compatible client at the URL shown in the popover.

Optionally, set an Instruction prompt in the popover first — a short persona like "You are an expert copy editor," applied once when a conversation starts. Use New Session (⌘N) to end the current conversation and try a different one.

4. Using this with a browser-hosted client (e.g. a Figma prototype)

If you're pointing a published web page at your local PePo instead of a native app, which browser you use matters:

  • Chrome/Edge — works against the plain http://127.0.0.1:<port> URL shown in the popover, no extra steps.
  • Safari — refuses to call a plain http:// endpoint from a page served over https://, with no workaround on the server's side. PePo also serves HTTPS for exactly this reason (on port + 1 by default), using a local certificate generated on first launch. In the popover, set Protocol to HTTPS and click Trust Certificate… once — macOS asks for your password, then adds the certificate to your login keychain. (It's your own Mac, talking to itself; the certificate only covers 127.0.0.1 and localhost.) After that, point your hosted page's requests at the https:// URL the popover shows. This works in Chrome/Edge too.
